## C. Key text clarity (cross-cutting, Vu, 2026-11-07)

Some key text is too terse (very compact, machine-written wording). That causes two problems: the rubric extractor splits it into the wrong points (R2 60: 30 of 337 points split inside a delimiter, and fragments like "no silent remove. Key from stat_boosts.v1.json: CM +1 spa" became points), and some keys are hard for a human to read, which makes the hand audit slower and the grading less consistent.

Proposed handling (not decided):
1. Keys that section A changes are rewritten in full in plain sentences, one expected behavior per point, with each point stating the condition ("if the pick has Intimidate"), the expected behavior, and whether it must be tool-backed.
2. Keys that section A does not change keep their meaning. The extractor reads points from an explicit structure (one point per list item or field in the key source), not from punctuation. A first pass by Cursor splits the existing key text mechanically into that structure with no wording changes, and flags every key where the split is ambiguous. You review the flagged ones and the section A rows; the rest are not reread.
3. A rewritten key must not change what counts as a pass unless section A says so. Cursor produces a diff of old and new points per row (point by point, old text beside new), so a meaning change cannot happen unnoticed.
4. Scope (decided, Vu, 2026-11-07): the smaller scope first, meaning the rows section A touches plus the 15 turns with a known bad split. The purpose is a more precise audit; widening is a later call.
